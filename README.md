# The Scriptures — liquid glass reader

A scripture study site: all five standard works with reference search
(autocomplete like "m 2 3" → Mosiah 2:3) and 1920 edition chapter
synopses over the current text.

## Run locally
    npm install
    npm run dev        # http://localhost:5173

## Build for production
    npm run build      # outputs to dist/

## Deploying to GitHub Pages
`.github/workflows/deploy.yml` builds and publishes on every push to `main`.
Enable it once under **Settings → Pages → Build and deployment → Source:
GitHub Actions**; no branch or `docs/` folder is involved.

The base path is not hard-coded — the workflow derives it from the repository
name, so `<user>.github.io` publishes at the root and any other repo name
publishes at `/<repo>/`. Renaming the repo needs no code change.

`npm run build` locally still uses `/`; set `SITE_BASE=/<repo>/ npm run build`
to reproduce exactly what the workflow produces.

## Structure
    src/App.jsx              state + routing between views
    src/components/          one file per UI piece
    src/data/volumes.js      the five standard works (CDN file names)
    src/data/bookIndex.js    all 87 books w/ chapter counts (powers search)
    src/data/synopses1920.json  1920 chapter synopses overlay (Book of Mormon)
    src/lib/search.js        reference parser + autocomplete
    src/lib/api.js           volume fetching + cache
    src/theme.js             glass styles + palette

## Adding study layers
Follow the synopses pattern: put new data (footnotes, cross-references,
variants) in src/data/ keyed by book → chapter, import it in Reader.jsx,
and render it as another overlay. The scripture text itself stays untouched.

## Sources and rights
**Chapter synopses** (`src/data/synopses1920.json`) come from the 1920 Salt
Lake City edition and are public domain.

**The personal summaries** in `public/local/summaries.json` are extracted from
the current editions and are copyrighted, so they never leave this machine:
they are gitignored, a Vite plugin deletes them from `dist/`, and the deploy
workflow fails if they reappear. The app treats the file as optional and falls
back to the 1920 synopses, which is what the published site shows.

**The verse text** for three volumes is built from public-domain sources by
`npm run build:scriptures` into `public/scriptures/`, and served from this site:

| Volume | Source | State |
|---|---|---|
| Old & New Testament | King James Version (aruljohn/Bible-kjv) | 1,189 chapters, 31,102 verses; every chapter matches the canonical verse counts |
| Book of Mormon | 1920 Salt Lake City edition, Internet Archive page scan | all 6,604 verses placed, agreement 0.996; no gaps |
| Pearl of Great Price | Talmage's 1902 versification (1913 printing), page scan | all 635 verses placed, agreement 0.980; no gaps |
| Doctrine and Covenants | Orson Pratt versification, Deseret News printing, page scan | 3,581 of 3,654 verses placed, agreement 0.987; 3 gaps |

**The manifest** in `src/data/manifest.json` is generated by
`npm run build:manifest` (run automatically before `npm run dev` and
`npm run build`), so it is regenerated rather than edited. It holds the small
facts about the site's own written pages — the charts, the evidences, the
translation essays and the prophets — that have to be known before any of them
is fetched: which volume has which, what each is called, and which chapters each
one treats. That last is read off the citations in the pages themselves, by the
same scan that turns them into links (`src/lib/cites.js`) and the same parsers
the pages are read with (`src/lib/*.parse.js`), so the manifest cannot come to
disagree with them.

It exists so the pages need not be. They are four fifths of the site's weight
and are loaded only when one is opened; adding a static `import` of
`lib/charts.js`, `lib/evidences.js`, `lib/essays.js` or `lib/prophets.js` to
anything reachable from `App.jsx` silently puts all of them back into the first
download, and nothing will look wrong. **If you add or edit a chart, an evidence,
an essay or a prophet, run `npm run build:manifest`** — or start the dev server,
which does it for you.

**The word-search index** in `public/search/` is generated from that verse text
by `npm run build:search` (also run automatically before `npm run build`), so it
is regenerated rather than edited. `meta.json` lists every chapter; the files
under `t/` map each word stem to the chapters and verses holding it, split by
the stem's first letters so a search downloads only the few kilobytes its own
words need. Words are reduced to stems by the Porter algorithm plus the King
James verb endings (`src/lib/stem.js`), which is why a search for "atonement"
also finds "atoneth" — the same file does the reducing on both sides.

The files under `w/` are the vocabulary — every word as the scriptures write
it, with how often, one file per first letter. They drive the suggestions while
you type and the "did you mean" offered when a search finds nothing. Because
they are drawn from the text itself, they include the scans' own OCR slips: a
misspelling that happens to match one will return that single verse rather than
a correction.

**The map** in `public/map/book-of-mormon.svg` is a vector trace of the standard
study map of Book of Mormon lands, prepared by `npm run build:map <traced.svg>`,
which rounds its coordinates to a tenth of a pixel (halving the file) and reports
the centre of every city dot it can find. Those centres are the exact positions
in `src/data/map/book-of-mormon.js`; the rest of the places there are placed by
eye and corrected onto the same frame of reference, close enough for the map's
search to fly to but not exact. The trace's own lettering dropped characters here
and there and is left as it is: a letter and a bush are the same size and much the
same colour, so removing one removes the other and tears holes in the terrain.

The geography is the one the record draws of itself — a land northward and a land
southward joined by a narrow neck, seas east and west — and is not a claim about
ground anywhere on earth.

Sections 137 and 138 were only added to the Doctrine and Covenants in 1979, so
no pre-1929 printing contains them. They read "[not in this edition]" rather
than being reported as scan damage.

The two scans are OCR of two-column settings, so the build separates scripture
from page furniture — running heads, page numbers, date banners and the
cross-reference apparatus at the foot of each page — and places each verse by
comparing wording with the modern edition. That comparison is used **only** as
a map of where a verse belongs; every word written out comes from the scan.
The remaining difference is a mix of genuine older readings ("a white and
delightsome people", "a descendant of Joseph") and leftover OCR damage. Verses
the scans did not yield are listed in `gaps.json` and say so in the reader
rather than appearing blank.

A short table of misreadings is corrected (`NephI`, `Jesns`, `Lamanltes`), and
a few words the scan capitalises mid-sentence are lowered. Both lists are
deliberately small: anything open to interpretation is left as the scan has it.

**Proofreading.** `npm run proof:scriptures` (`scripts/proofread-scriptures.mjs`)
goes over the three scanned volumes after they are built, and `build:scriptures`
runs it itself, so rebuilding from the scans does not undo it. It works in two
passes, and the modern edition stays what it is for the build: a map of where a
verse belongs, never a source of words.

The first pass puts verses back in their own slots. The build had placed some a
slot early, leaving `[not legible in the page scan]` behind them; had glued pairs
of verses together behind a mangled verse number ("3 9.", "1.4."); and had
shifted D&C 13–19 by most of a section, so those verses showed the words of the
ones after them. Each book is cut at every token that could be a verse number
and aligned in reading order. 137 verses that read as illegible turned out to
have their text in the scan all along, and the slots that were showing another
verse's words now say they are missing instead. A result is refused if it would
drop real words or make a verse that read well read worse, and the passages the
scan holds out of order are left exactly as scanned (Alma 62–63, Mormon
5–7, Ether 1–2, Moses 1–5 and 7–8, Joseph Smith—History, and D&C 76–78, 99–103,
123–125 and 134–136).

The second pass corrects words, but only a token that is not a word of scripture
at all, and only onto a spelling the scanned edition itself prints elsewhere. It
takes off fused footnote keys (`amy church`), stray letters, figures and
apparatus; rejoins words run together or split; and puts back misread letters
(`Nephl`, `npon`, `hiro`). A genuine older reading is a word, so it is left
alone — `Saviour`, `intrusted`, `Methusaleh` keep the edition's spelling — and
so are the names the older Doctrine and Covenants printed where the modern text
prints others (`Baurak Ale`). The few misreadings that happen to be English words
(`Availing` for *wailing*) are corrected from a short table checked by hand. Run
twice, it changes nothing the second time.

Last, it takes out printed matter that reached a verse through the
column-splitter without being verse at all: the headings the 1920 Book of Mormon
sets between chapters ("The Record of Zeniff. — An account of his people…"), the
Doctrine and Covenants' own section headings and running heads, the explanations
of the Book of Abraham's facsimiles, and back matter. That is real print, so each
piece is named by hand, and it comes out only if the verse reads closer to itself
without it. Two were scripture in the wrong place — a verse of Alma 61 and one of
Joseph Smith—Matthew — and went back to the verses they belong to. Between the
three steps, the list of verses marked illegible went from 195 to 93.

**Collation.** One scan of a book is wrong wherever that copy was smudged or its
OCR guessed badly, and other copies are wrong in other places.
`npm run collate:scriptures` (`scripts/collate-scriptures.mjs`) compares the site's
text with other scans of the same printings on the Internet Archive: eleven more
copies of the 1920 Book of Mormon, ten printings of Pratt's Doctrine and Covenants
from 1880 to 1908, and five of the Pearl of Great Price. They are downloaded once
into `scripts/.witnesses/`, which is not committed. Each verse is found in every
scan by the words it shares with the site's text and compared word by word.
Where at least two scans, and three in five of those holding the verse, agree
against the site's reading, it was the site's scan that erred: "tidings" for
*things*, "theft" for *that*, "multitu" for *multitude*, and 90 verses it could not
read at all. What they agree on is still the old printing's own wording. The
modern edition only checks that a change reads toward sense, and never supplies
a word.

Every copy of a printing carries the same footnote keys and headings, so every
scan agrees on those too, and agreement alone cannot tell them from the text.
That is why an added word has to make the verse read better, a removed one has
to be no word at all, and punctuation a scan set apart ("them ?") is joined up
rather than dropped. Readings every scan prints stay, however they differ from
the modern text: "the great mediation of all men" (2 Nephi 2:27), "the signal
which had been given" (3 Nephi 1:16). The settled readings are written to
`scripts/data/witness-readings.json`, and the proofreader applies each one to a
verse that still reads as it did when the scans were compared, so a rebuild
takes them all again and a second run changes nothing. With them, the verses
marked illegible are down to 3.

Project Gutenberg's Book of Mormon was not used as a witness: it reads "a pure
and delightsome people" at 2 Nephi 30:6, which is the 1981 wording.

No text is fetched from `bcbooks/scriptures-json` at runtime any more. That
dataset is the current (1981/2013) edition, © Intellectual Reserve — 2 Nephi
30:6 there reads "pure and a delightsome", wording introduced in 1981 — and the
build now uses it only as a map of where verses belong, never as a source of
words.

**Still owed:** the 3 verses in `gaps.json` (D&C 19:30, 109:17 and 109:18), which
no scan of these printings yielded, need keying in by hand, and so do the
out-of-order passages the proofreader leaves as scanned. What word damage remains
is where the scans misread a word the same way, or all lose part of one
("percuted", D&C 45:53): correcting those would mean supplying letters no page
gives, so they are left for a person to check against a printed copy.
